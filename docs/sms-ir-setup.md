# پیامک SMS.ir — نسخهٔ 15.0.0

## وضعیت راه‌اندازی

- مستند رسمی در Chrome بررسی شد: https://app.sms.ir/developer/help/introduction
- کلید ارائه‌شده با `GET https://api.sms.ir/v1/credit` اعتبارسنجی شد: HTTP 200 و status=1. پیامکی در آزمایش واقعی ارسال نشد.
- قالب OTP با عنوان «کد تأیید موبایل منتوریس»، شناسهٔ **235630** و پارامتر **CODE** ثبت شد؛ هنگام ثبت، وضعیت «در حال بررسی» بود. متن کوتاه یک بخش پیامکی است:

```text
منتوریس
کد تأیید: #CODE#
اعتبار: ۵ دقیقه. کد را به کسی ندهید.
```

ارسال از endpoint رسمی `POST https://api.sms.ir/v1/send/verify` با هدر `X-API-KEY` انجام می‌شود. success فقط وقتی HTTP=200، status=1 و messageId معتبر باشد پذیرفته می‌شود. پذیرش سرویس تضمین تحویل به گوشی نیست.

## نصب روی هاست

۱. کد جدید GitHub را Update from Remote و سپس Deploy HEAD کنید. فایل‌های `.env` و داده‌های جاری را نگه دارید. CSS/JS صفحه باید نسخهٔ **15.0.0** داشته باشد.

۲. در phpMyAdmin دیتابیس فعلی سایت را انتخاب و فایل `database/cpanel/sms_upgrade_2026_10_04.mysql.sql` را Import کنید. این فایل فقط سه جدول جدید را با `CREATE TABLE IF NOT EXISTS` اضافه می‌کند؛ جدول کاربران تغییر نمی‌کند و اطلاعات قبلی حذف نمی‌شود. برای دیتابیس با نسخهٔ نامعلوم، `latest_schema_2026_10_04.mysql.sql` نسخهٔ کامل ۳۳جدولی است. `verify_mentoris_schema.mysql.sql` بررسی فقط‌خواندنی است.

۳. تنظیمات آماده و **خصوصی** در `storage/temp/sms-host.env` کامپیوتر شما قرار دارد و وارد Git نشده است. محتوا را با `.env` فعلی هاست ادغام کنید؛ فایل کامل `.env` را جایگزین نکنید و این فایل خصوصی را در مسیر عمومی آپلود نکنید. ساختار تنظیمات:

```dotenv
SMS_ENABLED=false
SMS_IR_API_KEY=YOUR_PRIVATE_KEY
SMS_IR_OTP_TEMPLATE_ID=235630
SMS_IR_OTP_PARAMETER=CODE
SMS_DAILY_LIMIT=40
SMS_HOURLY_LIMIT=10
RATE_LIMIT_DRIVER=files
```

۴. پس از تأیید قالب توسط SMS.ir، `SMS_ENABLED=true` کنید. PHP نیازمند cURL، PDO MySQL، OpenSSL و امکان اتصال HTTPS به `api.sms.ir` است. تأیید TLS را غیرفعال نکنید؛ اگر گواهی CA ناقص بود، تنظیم CA هاست را اصلاح کنید. در محیط واقعی `APP_ENV=production` و `APP_DEBUG=false` باشد و `APP_KEY` فعلی و امن را حفظ کنید.

۵. با حساب خود وارد پروفایل شوید، شمارهٔ خود را ذخیره کنید، کد درخواست و تأیید کنید. در `/admin/sms` سهمیه، درخواست‌ها، خطاها و شماره‌های تأییدشده دیده می‌شود. با `SMS_ENABLED=false` ارسال فوراً متوقف می‌شود.

۶. بررسی فقط‌خواندنی اتصال از ترمینال هاست: `php bin/sms-health.php`. این فرمان کلید یا پاسخ خام را چاپ نمی‌کند و پیامک نمی‌فرستد.

## رفتار و محدودیت‌ها

- ثبت‌نام و تکمیل پروفایل بدون تأیید موبایل ادامه دارد؛ تأیید در پروفایل اختیاری است. خاموش‌بودن پیامک، تأیید‌نشدن قالب و نصب‌نشدن SQL فرم عضویت را خراب نمی‌کند.
- فقط کاربر فعال و واردشده با CSRF معتبر به شمارهٔ ذخیره‌شدهٔ خودش کد می‌فرستد. مقصد، متن و قالب از ورودی کاربر گرفته نمی‌شود. ورود و بازیابی رمز با شمارهٔ تأییدنشده اضافه نشده‌اند.
- کد تصادفی شش‌رقمی، اعتبار ۵ دقیقه، ۵ تلاش، مصرف فقط یک‌بار؛ در دیتابیس فقط HMAC وابسته به حساب، شماره و شناسهٔ چالش ذخیره می‌شود. تغییر شماره کد قبلی و نمایش وضعیت تأیید آن شماره را بی‌اعتبار می‌کند. شمارهٔ تأییدشده نمی‌تواند هم‌زمان به دو حساب تعلق بگیرد.
- تغییر شماره از پروفایل یا مدیریت، تأیید و چالش قبلی را در همان تراکنش حذف می‌کند؛ شمارهٔ قبلی برای مالک بعدی آزاد می‌شود. ذخیرهٔ نام بدون تغییر شماره، تأیید را حفظ می‌کند.
- هر حساب و هر شماره: فاصلهٔ ۹۰ ثانیه، ۳ درخواست در ساعت، ۵ درخواست در ۲۴ ساعت. هر IP: ۱۰ در ساعت و ۲۰ در ۲۴ ساعت. کل سایت: پیش‌فرض ۱۰ در ساعت و ۴۰ در ۲۴ ساعت؛ قابل کاهش از `.env`، با سقف سخت ۱۰۰۰ در ۲۴ ساعت.
- سهمیه‌ها بازه‌های ثابت از اولین درخواست هستند، روز تقویمی نیستند. تمام سهمیه‌ها و چالش قبل از تماس شبکه در یک تراکنش رزرو می‌شوند. از سهمیهٔ ارسال ناموفق/نامشخص هم کم می‌شود و هیچ تکرار خودکاری برای ارسال وجود ندارد.
- هزینهٔ ریالی نهایی به تعرفه و متن تأییدشدهٔ سرویس وابسته است. این محدودیت سقف **درخواست ارسال** است؛ برای همین قالب فعلی به یک بخش کوتاه محدود شده است. برای متن چندبخشی، سقف را متناسب کاهش دهید.
- کلید API و کد خام در گزارش، پاسخ HTTP یا Git ذخیره نمی‌شوند. مقصد HTTPS ثابت، بررسی TLS فعال، redirect خاموش، timeout محدود و حداکثر پاسخ ۱۶ کیلوبایت است.
- پاسخ صفحات ورود، پروفایل و مدیریت با `Cache-Control: private, no-store` محافظت می‌شود و debug در محیط production غیرفعال است، حتی اگر APP_DEBUG اشتباه تنظیم شده باشد.
- ریت‌لیمیت عمومی وابسته به کوکی حذف شده؛ `files` با قفل اتمیک برای یک هاست استفاده می‌شود. حتی مقدار قدیمی `session` هم اکنون به فایل پایدار نگاشت می‌شود. برای چند سرور/محیط serverless از `RATE_LIMIT_DRIVER=database` استفاده کنید. سهمیهٔ پیامک همیشه دیتابیسی است. خرابی ذخیرهٔ محدودیت، درخواست را رد می‌کند.
- فایل‌های محدودیت زیر `storage/data/rate-limits` خصوصی‌اند. برای جلوگیری از افزایش بلندمدت فایل‌ها، نگهداری دوره‌ای فایل‌های قدیمی را هنگام توقف موقت ترافیک انجام دهید؛ حذف bucketهای فعال محدودیت را ریست می‌کند. پیش از API، WAF/CDN و کنترل اتصال/بدنهٔ درخواست هاست هم برای مقابله با سیل ترافیک مفید است.

## اعتبارسنجی

`php tests/Feature/sms-flow.php`: OTP، عدم افشای کد، replay، انقضا، ۵ تلاش، تغییر شماره، مالکیت شماره، رد سرویس، timeout بدون retry، سقف مشترک سایت و ۲۴ worker هم‌زمان برای رزرو سهمیهٔ SQLite/فایل. تست‌ها از transport ساختگی و دیتابیس جدا استفاده می‌کنند؛ پیامک واقعی نمی‌فرستند.

`php tests/Feature/member-flow.php`: مسیرهای واقعی فرم عضویت/پروفایل، نیاز CSRF پیامک، مسدودبودن پنل SMS برای عضو عادی و جلوگیری از ارسال حساب تعلیق‌شده؛ رندر پروفایل و پنل پیامک حتی قبل از SQL جدید.

این تغییرها تضمین «صفر آسیب‌پذیری» برای تمام سایت و زیرساخت نیستند. تحویل واقعی به موبایل و رفتار هم‌زمان MySQL هاست پس از نصب باید بررسی شوند؛ تست هم‌زمان محلی با SQLite و فایل انجام شده است.
