# درخواست حلقه، مرور اطلاعات و پرداخت

- فایل رزومه اختیاری است؛ نبودن آن مانع ثبت درخواست نمی‌شود. سوابق حرفه‌ای ضروری و تکمیل پروفایل همچنان بررسی می‌شوند.
- اطلاعات هر درخواست در `circle_applications` و شهر در `event_signups` ذخیره می‌شود. فرم بعدی از آخرین درخواست مربوط به `user_id` همان حساب پر می‌شود و قابل ویرایش است؛ نام و شماره از حساب احراز‌شده خوانده می‌شوند.
- اگر رزومه قبلی موجود باشد، استفاده مجدد با یک تیک مشخص نمایش داده می‌شود. فایل جدید جایگزین پیوست درخواست جدید می‌شود؛ فایل درخواست‌های قبلی حذف نمی‌شود. فایل‌ها خصوصی‌اند و دانلود مدیر نیازمند مجوز مشاهده درخواست‌هاست.
- پیش از ارسال، خلاصه اطلاعات در پنجره قابل مرور نمایش داده می‌شود. کاربر می‌تواند ویرایش کند یا ارسال نهایی را تأیید کند. بدون JavaScript فرم معمولی همچنان قابل ارسال است.
- صفحه کارت‌به‌کارت خلاصه مبلغ، سه مرحله پرداخت، کارت قابل کپی و بخش مستقل ارسال رسید دارد. تخفیف، اقساط و بررسی مدیر حفظ شده‌اند.
- ساختار دیتابیس تغییر نکرده است. نبودن رزومه به صورت JSON `null` در ستون JSON موجود ذخیره می‌شود؛ این مقدار با `SQL NULL` متفاوت است و با `NOT NULL` سازگار است. نصب‌هایی که مهاجرت ۱۱ را ندارند باید SQL کامل قبلی را اجرا کنند.

برای انتشار این اصلاحات فقط کدها را Deploy کنید. بررسی‌های خودکار در `tests/Feature/circle-application-reuse.php` از دیتابیس مجزا استفاده می‌کنند و پیام واقعی ارسال نمی‌کنند.

در مرورگر محلی، درخواست واقعی بدون رزومه ثبت شد و مقدار اطلاعات از دیتابیس مستقل خوانده شد. فرم یک رویداد دیگر با همان اطلاعات پر شد. مرور اطلاعات، ویرایش قبل از تأیید، مبلغ ۷٫۵ میلیون تومانی هر قسط و کپی دقیق شماره کارت بررسی شدند. صفحه پرداخت در عرض ۳۹۰ و ۱۳۶۵ پیکسل سرریز افقی و خطای JavaScript نداشت.
